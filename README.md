# MVP-Paytool-Bot

## Функционал

### Для пользователей
- Главное меню с кнопками: пополнение Steam, бонус +50 ₽, отзывы, FAQ, гарантии, личный кабинет, поддержка, другие товары, актуальные скидки, канал, сайт.
- Бонус +50 ₽ на первую покупку (однократно).
- Личный кабинет: общее количество покупок и баланс «Донатов».
- Гарантии: юридическая информация, ссылки на оферту/политику и офис компании.
- Поддержка: быстрый переход в чат поддержки.
- Справка по региону Steam + картинка-инструкция.
- Все тексты отправляются без HTML/Markdown (plain-text с эмодзи).

### Для администраторов
- Скрытая кнопка «🛠 Админ-панель» — видна только админам (по ID из .env).
- Редактирование приветственного текста (через диалог).
- Статистика: количество пользователей.
- Рассылки:
    - Создание кампании: название, текст, опционально — медиа (фото/видео/док), кнопка-ссылка.
    - Сегментация:
        - все пользователи;
        - новые (зарегистрировались ≤ 7 дней назад);
        - есть покупки / нет покупок;
        - покупали за 7/30/90 дней (нужно отмечать last_purchase_at при реальной покупке);
        - открывали бота за X дней;
        - по списку ID.
    - Типы: мгновенная («Отправить сейчас») и отложенная по времени (ввод в UTC).
    - История рассылок: список с ID, статусом, типом, план-временем, статистикой отправлено/ошибок.
    - Фоновый планировщик: раз в ~10 сек проверяет и запускает отложенные кампании.
- Логгирование входящих сообщений и фиксация активности пользователя (последний визит).

- Python 3.12

## Настройка окружения

создайте `.env` в корне:

```bash
BOT_TOKEN=123456:ABCDEF...        # токен бота
ADMINS=111111111,222222222        # список ID админов через запятую (целые числа)
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_DB=0
```

- Узнать свой Telegram ID можно через бота @userinfobot.

## Redis (Docker Compose)
создайте `docker-compose.yml` (если его нет) в корне проекта:
```yaml
version: '3.8'

services:
  redis:
    image: redis:7-alpine
    container_name: MVP-Paytool-Bot_redis
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes"]
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

volumes:
  redis_data:
```
запуск:
```bash
docker compose up -d
```
проверка:
```bash
docker ps                                 # должен быть контейнер MVP-Paytool-Bot_redis
docker exec -it MVP-Paytool-Bot_redis redis-cli
PING                                      # ответ: PONG
```

1. активируйте venv и проверьте .env.

## Админ-панель: как пользоваться
1. Нажмите 🛠 Админ-панель.
2. Доступные действия:
    - ✏️ Редактировать приветственный текст — бот попросит ввести новый текст → сохранит в Redis → выдаст подтверждение.
    - 📊 Статистика — покажет число зарегистрированных пользователей.
    - 📣 Создать рассылку — пошаговый мастер:
        1. Название рассылки (внутреннее).
        2. Текст (plain-text, эмодзи ок, без HTML/Markdown).
        3. Медиа (фото/видео/документ) — отправьте файл одним сообщением или напишите «Без медиа».
        4. Кнопка — Текст кнопки | https://url или «Без кнопки».
        5. Сегмент аудитории:
            - Все пользователи
            - Новые пользователи (≤ 7 дней от регистрации)
            - Есть покупки / Нет покупок
            - Покупали за 7/30/90 дней
            - Открывали бота X дней (введите число)
            vПо списку ID (введите 111,222,333)
        6. Тип рассылки:
            - 🚀 Отправить сейчас — пойдёт в работу сразу.
            - ⏰ Запланировать — введите дату/время в формате YYYY-MM-DD HH:MM по UTC.
            - 🗂 История рассылок — последние кампании: ID, статус (pending/scheduled/sending/done), тип, план-время, счётчики sent/failed.
- Отложенные рассылки запускает фоновый планировщик внутри main.py (задача scheduler_loop, проверка каждые ~10 секунд).

## Данные в Redis

`users:all` — множество всех `user_id`.

`user:{id}:profile` — hash с полями `username`, `first_name`, `last_name`, `joined_at`.

`user:{id}:donates` — баланс донатов (int).

`user:{id}:purchases` — количество покупок (int).

`user:{id}:bonus_received` — «1», если бонус выдан.

`user:{id}:last_seen` — ISO-время последнего визита (для сегмента «открывали за X дней»).

`user:{id}:last_purchase_at` — ISO-время последней покупки (для сегментов «покупали за N дней»).

`welcome_text` — текущий приветственный текст.

Кампании рассылок:

`campaigns:seq` — автоинкремент ID.

`campaigns:all` — множество campaign_id.

`campaign:{id}` — hash с полями кампании (title, text, media_type, file_id, button_text/url, audience, type, schedule_at, status и т.д.).

`campaign:{id}:stats` — hash со статистикой (`sent`, `failed`, `total`, `started_at`, `finished_at`).

## Про время
- Ввод плановой даты/времени рассылки — в UTC (например, 2025-12-31 23:59).
- Если вы работаете в другом часовом поясе — конвертируйте время самостоятельно (например, Europe/Moscow → UTC).
- Проверка планировщика идёт примерно каждые 10 секунд.

## Как быстро проверить рассылку на тестовой группе

1. В `.env` добавьте себя в ADMINS.
2. В Telegram у бота нажмите 🛠 Админ-панель → 📣 Создать рассылку.
3. Пройдите мастер, выберите «По списку ID» и укажите свой user_id.
4. Выберите «🚀 Отправить сейчас».
5. Сообщение должно прийти сразу.

## Траблшутинг

- `Ошибка при инициализации бота: ...`
Проверьте `BOT_TOKEN` в `.env`.
- redis.exceptions.ConnectionError
Проверьте, что Redis поднят: `docker compose up -d` и `PING → PONG`.
- Админ-кнопки не видны
Убедитесь, что ваш ID указан в ADMINS и бот перезапущен.
- Отложенная рассылка не стартует
Проверьте формат даты (`YYYY-MM-DD HH:MM`), что это UTC, и подождите 10–20 сек (цикл планировщика).
- Медиа не прикрепилось
Отправляйте файлы в одном сообщении на шаге «Приложить медиа?».
- `TelegramForbiddenError` при рассылке
Пользователь мог заблокировать бота; такие отправки учитываются в `failed`.

## Безопасность и ограничения
- Рассылки идут plain-text (без HTML/Markdown).
- Кнопка в рассылке — только внешняя ссылка (inline-кнопка с URL).
- Rate-limit Telegram учитывается (при RetryAfter бот ждёт и продолжает).

## Деплой

1. Установите Python 3.12, создайте venv, поставьте зависимости.
2. Поднимите Redis (можно тем же `docker-compose.yml`).
3. Пропишите `.env` с реальным `BOT_TOKEN` и `ADMINS`.
4. Добавьте процесс-менеджер (например, `systemd`):
`/etc/systemd/system/mvp-paytool-bot.service:`
```ini
[Unit]
Description=MVP Paytool Bot
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/MVP-Paytool-Bot
Environment="BOT_TOKEN=xxx" "ADMINS=111,222" "REDIS_HOST=127.0.0.1" "REDIS_PORT=6379" "REDIS_DB=0"
ExecStart=/opt/MVP-Paytool-Bot/.venv/bin/python main.py
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable mvp-paytool-bot
sudo systemctl start mvp-paytool-bot
sudo journalctl -u mvp-paytool-bot -f
```
